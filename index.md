Step 1: URL Parsing & DNS ResolutionURL Breakdown: The browser parses the string to identify the scheme (https://), host (example.com), port (443 for HTTPS, 80 for HTTP), and path (/index.html).Cache Hierarchy Check: Before hitting the network, the browser checks:Browser cacheOperating system DNS cacheRouter cacheDNS Query: If unresolved, the OS contacts the configured recursive DNS resolver (often provided by the ISP or public services like 1.1.1.1/8.8.8.8), traversing:Root nameserver (.)Top-Level Domain (TLD) nameserver (.com)Authoritative nameserver (example.com)Result: The authoritative server returns the IP address (IPv4/IPv6).Step 2: Connection Establishment (TCP & TLS)TCP 3-Way Handshake: The browser initiates a reliable connection with the server IP:SYN (Browser $\rightarrow$ Server)SYN-ACK (Server $\rightarrow$ Browser)ACK (Browser $\rightarrow$ Server)TLS Handshake (HTTPS):The client and server agree on a TLS version and cipher suite.The server provides its SSL/TLS certificate, verified against trusted Certificate Authorities (CAs).Session keys are exchanged via asymmetric cryptography (e.g., Diffie-Hellman), enabling fast, symmetric encryption for all subsequent traffic.Step 3: HTTP Request & Server ResponseSending the Request: The browser constructs an HTTP request:HTTPGET /index.html HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0 ...
Accept: text/html
Server-Side Handling: The web server (or reverse proxy like Nginx/Cloudflare) receives the payload, passes it to the backend application if dynamic, or pulls the static file from storage.Server Response: The server sends back an HTTP response containing headers, a status code (200 OK, 301 Redirect, 404 Not Found), and the HTML payload:HTTPHTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8

Step 4: Critical Rendering Path (CRP)DOM Construction: The browser tokenizes raw HTML bytes, turns them into nodes, and builds the Document Object Model (DOM) tree.Resource Discovery: As the HTML parser encounters external tags (<link rel="stylesheet">, <script>, <img>), it fires secondary network requests.CSSOM Construction: CSS rules are tokenized and organized into the CSS Object Model (CSSOM) tree. CSS is render-blocking.Render Tree: The DOM and CSSOM combine. Only visible nodes are included (elements with display: none or <head> tags are omitted).Layout (Reflow): The browser calculates the exact geometry, box sizing, and coordinates for every visible element relative to the viewport.Paint: The browser converts vectors and layout boxes into actual screen pixels (rasterization), separating layers (e.g., transforms or fixed elements) for efficiency.Compositing: The GPU composites the different layers onto the physical display screen.Step 5: JavaScript Execution & InteractivityScript Processing: JavaScript can block HTML parsing unless marked with defer or async.Engine Execution: The JavaScript engine (V8, SpiderMonkey, JavaScriptCore) compiles and executes code.Event Loop & DOM Updates: Scripts attach event listeners (click, scroll) and mutate the DOM or CSSOM via API calls, triggering layout updates or repaints dynamically.
